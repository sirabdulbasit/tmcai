## 3. The mistake worth reading before you touch anything

**In D-89 I reported the month-old `22021` loop as diagnosed and fixed. It was not.**

I found that a NUL in a bind parameter raises exactly `22021`, reproduced it against the live
database, built `rawParamSanitizer.ts`, proved it end to end, shipped it, and wrote it up as the
cause. Five more occurrences appeared **74 minutes later**.

The real cause (DEF-303): `substring()` on a TOAST-**compressed** column can be served from a
*partial* detoast whose slice ends mid-character. On the same row, `left(…,799)` works,
`left(…,800)` fails, `left(…,801)` works, and reading the whole column always works. The failure
depends on where you cut, not on what the row holds — which is why three earlier attempts
(DEF-085, DEF-252, DEF-289) each added attribution instead of a cause.

Two lessons, both of which cost real time today:

- **A reproduction is not a diagnosis.** The parameter bug was real and is still fixed. It simply
  was not the one firing.
- **The check that finds my mistakes is running the thing, not reading it.** Every wrong version
  today passed a green matrix. What caught them was reading the error log after the deploy, and
  rendering prompt blocks against live data.

`rawParamSanitizer` is kept — it closes a real failure mode that is otherwise still reachable.

## 7. Things that will bite you

- **Another session edits the same files.** Today one rewrote `dispatchLedgerService` into a merged
  list mid-flight, and two of my string replacements silently did nothing because I had asserted on
  some replacements and not those two. **Assert on every replacement.** The 10-minute loop is off
  now, but the nightly one still runs.
- **`server/dist` is immutable and the build is not in the verification matrix.** `--noEmit` is the
  build check. Unlock only inside a deploy, predict the manifest from a clean clone *first*, and
  relock. That prediction caught a non-building HEAD earlier this week.
- **Migration appliers that split on `;`.** One of mine cut a statement in half because a SQL
  comment contained a semicolon. Strip inline comments before splitting, and verify the columns or
  constraints afterwards.
- **Backticks and apostrophes inside SQL template literals** broke the build twice today.
- **Guards anchored on exact prose.** `chat22` needed re-anchoring twice in one day because the
  header text improved. Anchor on the stable substring, and assert the slice is non-empty — the
  first version passed vacuously on an empty string.
- **`cd` slips.** `git add server/docs/...` from inside `server/` fails; several of mine did.
